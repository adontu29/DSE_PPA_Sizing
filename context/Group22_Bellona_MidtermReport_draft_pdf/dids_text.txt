The Project Plan

3. DESCRIPTION
The purpose of the Project Plan is to define the group's overall approach to the technical and management
aspects of the design project. The document provides a complete roadmap of how the group plans to
accomplish all the necessary tasks to prepare the design. It represents a commitment by the group for work to
be accomplished on the Project. The customer does not want a detailed discussion of a particular design
approach, but the approach that shows how the design will be developed through studies, trade-offs, reviews
and analysis.

The maximum number of pages is 25 everything included, and is specified by the OSCC.

For large logical diagrams, you are allowed to include A3 pages in you report:
- 2 for the Work Flow Diagram
- 2 for the Work Breakdown Structure
- 2 for the Gantt Chart
Each A3 page counts as 1 page towards the page limit. These are specifically to be used for their deliverables,
and can not be “traded” to be used elsewhere.

6. APPLICATION/INTERRELATIONSHIP
Submittal of this document shall be in the form of a concise written explanation of exactly what you are
committing to deliver and how you intend to fulfil that commitment.

7. PREPARATION INSTRUCTIONS
The Project Plan must show that the group understands the requirements. It has to present a flow of activities
that eventually will result in a product that meets these requirements. The plan must explicitly state what
services are to be performed at what moments in time and what will be delivered (i.e., briefings, reports, etc.).

    The plan will be evaluated on quality, not quantity. All written pages must be typewritten. The plan format

Baseline Report

3. DESCRIPTION
The Baseline Report includes the Requirements Analysis to review and analyse the top-level (user) requirements in
combination with a flowdown in mission and system requirements. The document should give a clear picture about
all applicable requirements and identify the driving and any killer requirements.

The Baseline Report is a Technical Design Report.

Your group may define the format of the report, fitting in the template ("huisstijl") of TU Delft.
The maximum number of pages is 50 everything included, and is specified by the OSCC.

For large logical diagrams, you are allowed to include A3 pages in you report:
- 2 for the Functional Flow Diagram
- 1 for the Functional Breakdown Structure
- 1 for the Design Option Tree(s)
- 1 for the Requirements Discovery Tree
Each A3 page counts as 1 page towards the page limit. These are specifically to be used for their deliverables, and
can not be “traded” to be used elsewhere.


The report is a stand-alone document.

4. APPROVAL DATE                                                  5. CONFIGURATION CONTROL
                              April 12, 2018                                 OSCC (E.Mooij/W. Verhagen)
6. APPLICATION/INTERRELATIONSHIP
The Technical Design Report is a “living” document that reflects the current state of the project design.


7. PREPARATION INSTRUCTIONS
The engineering information to be included in this document is in part given by the deliverable items in the table in
Section 2.5. In addition, the report should include:

1.   Executive Overview (3 pages min, 10 pages, max)
2.   Project Objectives
3.   Requirements and Constraints;
a.   The Requirements Specification must clearly demonstrate that the group understands the user requirements,
and identify which requirements will drive the actual design of the product to be developed
b.   From the User Requirements the System and Mission Requirements should be derived, and potential sub-
system requirements that have an effect on the design options at system level
4.   Given the User Requirements, a (set of) Design Option Tree(s) with all potential solutions should be provided;
from this the design options for the Midterm Phase are selected.
5.   Level of detail of concepts discussion should be sufficient to understand the choices made
